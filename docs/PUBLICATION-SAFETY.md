# Publication Safety Contract

Public knowledge is produced through: private evidence → candidate → classify → minimize → redact → secret/PII/internal-data scan → claim/source verification → preview/review → publication → freshness monitoring.

## Block from public publication
Credentials/tokens/private keys; unnecessary PII; private account/seller/customer/order identifiers; raw private support conversations/logs; private source; internal hostnames/filesystem paths/private repo URLs when unnecessary; proprietary implementation detail; unpublished vulnerabilities; unsupported claims.

## Required for publishable problem/case knowledge
Stable problem ID; useful generalized customer intent; official terminology; sanitized symptoms; diagnostics; safe action boundary; verification method; provenance/source; privacy classification; last_verified; review_after when drift is plausible.

Generated successfully does not mean indexed, cited, accepted, executed, or verified in production.
